# TransfHAR 论文精读 · 30 分钟讲稿

论文：Bradshaw 等，TransfHAR: Self-Supervised Wrist Representations for On-Demand Activity Recognition，arXiv:2608.15861v2，CC BY 4.0。

共 10 节，建议时长 30 分钟，包含交互演示。模型结构示意与工程建议均以网页中的证据说明为准。

## 01. TransfHAR：让手表认识你的动作（2.5 分钟）

今天介绍的论文是 TransfHAR，它研究如何让智能手表用少量个人示范识别新的腕部动作。

论文把预训练数据中的粗粒度活动与下游的细粒度活动区分开来。粗粒度活动主要包括坐、站、躺等近静态姿态，以及走路、跑步、骑车和重复锻炼等整体运动。细粒度活动包括切菜、搅拌、写字、打响指和挥手等手部操作或手势，以及护肤、制作饮品等包含多个步骤的活动。这个划分依据腕部信号的运动结构，不是单纯按照动作名称或类别数量划分。

作者首先利用大量不依赖动作类别标签的腕部惯性数据训练编码器，让模型学习运动表示。随后冻结编码器，由用户为自己关心的类别提供少量有标签示范，只训练一个轻量线性分类器。论文要检验的是，从粗粒度活动学到的表示能否迁移到训练时未见的细粒度活动。

这是一种少样本个性化方法：新增类别仍然需要用户提供标注示范，模型不能只根据文字名称识别任意动作。论文的贡献集中在腕部数据整合、跨粒度迁移验证，以及手表端的个人化流程。

来源：摘要、§1、图1。

## 02. 数据的形状：从走路到操作步骤（2 分钟）

作者按照腕部信号的运动结构，将活动分为四级。L1 是近静态活动，信号主要由重力和缓慢姿态变化构成；L2 是步行等具有准周期结构的运动。L3 是幅度变化较大、通常不具有稳定周期的手部操作；L4 是过程步骤，短窗口内可能与 L3 相似，还需要结合更长时间的步骤上下文。

图3汇总的公开数据中，L1 约为1864小时，L2 约为677小时，L3 和 L4 所占比例小得多。这是数据集的汇总分布，不等同于全部用于预训练的时长。作者从预训练来源中选择 L1 和 L2 活动，并将下游评估数据集整体保留。

三轴和六轴版本的预训练数据规模也不同。六轴版本需要同时包含加速度与陀螺仪数据的来源，因此两者的表现差异不能只归因于是否加入陀螺仪。

## 03. 把不同 IMU 整理成同一种输入（2.5 分钟）

不同公开数据集的采样率、设备和佩戴方向并不一致，作者首先统一腕部信号的坐标和采样频率。坐标采用前、左、上的 FLU 约定，采样频率统一为50赫兹。三轴版本使用三轴加速度，六轴版本再加入三轴角速度。

每个窗口长2.56秒，因此每个通道包含128个采样点。相邻窗口重叠50%，步长为64个采样点，也就是1.28秒。每个窗口的各通道分别进行 z-score 标准化，得到三乘128或六乘128的输入。

论文正文对24赫兹低通与重采样的顺序描述，与部分原始数据的采样率及图4的表述之间存在需要进一步核实之处。标准化也会改变绝对幅值与偏置的信息，具体影响需要结合任务评估。

来源：表1、§3.1、§4.1.3。

## 04. 四个采样点，如何变成一个 Token？（3 分钟）

窗口进入模型后，每个传感器轴的128个采样点被切成32段，每段包含连续四个点。六轴输入共有192个 token，三轴输入共有96个 token。各轴共享同一套一维卷积投影参数，卷积核长度和步长均为4。

每段四个采样值通过可学习的线性投影变成一个384维向量，不是简单求平均。随后，模型将该向量与时间位置嵌入、传感器轴嵌入逐维相加，让 token 同时携带信号内容、时间位置和通道身份。这里的时间指2.56秒窗口内部的相对位置，不是实际的时钟时间。时间位置向量是随模型一起训练的参数：遮挡重建损失经过反向传播更新这些向量，不需要单独标注时间位置。预训练结束后，编码器及其位置参数在个人分类阶段保持冻结。

预训练时，被遮挡的 token 不进入编码器，未遮挡 token 仍保留自己的位置信息；遮挡位置的索引用于解码阶段。四个采样点在50赫兹下对应0.08秒，它与窗口之间50%的重叠属于两个不同层次。

来源：§4.1.2–4.1.3、图4。

## 05. ViT-1D 与遮挡重建（5 分钟）

作者使用 ViT-1D 编码器：12 层 Transformer、隐藏维度 384、6 个注意力头。每个 token 带着对应的时间位置与传感器轴身份进入网络，注意力让不同片段交换上下文。

预训练不使用动作类别标签，而是隐藏约 65% 的 token。作者采用随机、时间和通道三种遮挡；编码器只处理可见 token。六轴窗口共有 192 个 token，若示意性地遮挡 125 个，编码器输出约为批量乘以 67 乘以 384；具体取整以实现为准。

解码时，在缺失位置插入可学习的 mask token。这是新的占位向量，不是放回被遮挡的原始信号。编码器宽度为 384、解码器宽度为 192，因此需要维度适配；可以把逐 token 投影视为一种解释，论文没有明确投影与插入的先后。此时保留位置序列，不进行均值池化。四层解码器重建信号，均方误差只在遮挡位置计算。

下游个人识别是另一条路径：丢弃解码器，完整 token 序列通过冻结的编码器，再沿 token 维度逐维取均值，得到 384 维窗口表示，交给个人分类头。

来源：图4、§4.1.2–4.1.4。

## 06. 把通用表示变成个人分类器（3 分钟）

进入个性化阶段后，编码器的参数保持冻结。每个输入窗口被转换为384维表示，线性分类器再将这个表示映射到用户定义的活动类别。

如果有 C 个类别，每类对应384个权重和一个偏置，分类头共有385乘以 C 个参数。七类活动对应2695个参数。用户提供新的带标签示范后，系统训练或重训这个小型分类头，而不需要重新训练整个 Transformer。

作者使用加权交叉熵处理类别不平衡，并以验证集平衡准确率选择检查点。分类头虽小，冻结编码器仍然需要存储空间和计算资源。

来源：图5、§4.2。

## 07. 离线实验：迁移到底有没有用？（3 分钟）

作者使用三个未参与预训练的下游任务检验迁移。完整训练划分下，六轴冻结编码器加线性探针在 SAMoSA 上的平衡准确率为64.9%，公开监督基线为56.8%；PrISM 制作拿铁任务为36.5%对31.0%；UTD-MHAD 为69.1%对64.1%。差异分别为8.1、5.5和5.0个百分点，平均为6.2个百分点。

这里的公开监督基线是对应数据集既有研究中的全监督运动识别模型，使用带标签数据训练，并不特指传统机器学习方法。TransfHAR 的下游线性探针同样使用标签，差别在于前面有自监督预训练且编码器冻结。公开基线的模型和输入并不完全相同，部分基线使用九轴数据。因此作者还比较了相同六轴架构下的从头训练、预训练后微调和冻结探针。这些结果支持预训练表示在所测试设置中的价值，但不能推出冻结探针对所有任务都最优。

平衡准确率是各类别召回率的平均。不同窗口长度的比较显示，两个 L3 数据集在2.56秒窗口下表现最高，而 PrISM 拿铁任务在5.12秒窗口下表现最高，说明时间上下文的作用需要结合具体任务判断。

来源：图6、表3、§5.2–5.3。

## 08. 用户实验：示范几次够用吗？（3.5 分钟）

用户研究共有10位参与者，每人选择7类活动，每类录制三个独立的一分钟会话，会话之间摘下并重戴手表。作者每次用其中一轮训练，另外两轮测试，并轮换训练会话。每个训练窗口先通过冻结的预训练编码器，并对编码后的 token 做均值池化，得到384维特征。该特征和录制时的活动标签组成训练样本；每位参与者单独训练一个七分类线性头，只更新其权重和偏置，共2695个参数。测试时，另外两次独立录制经过相同处理并用这个头预测。

六轴模型每类随机抽取1个训练窗口时，平均平衡准确率为75.2%；每类5个为86.7%，每类20个为89.3%；使用完整一分钟训练录制时为90.4%。每类5个窗口是从整段一分钟训练会话中随机抽取的，相邻窗口也可能重叠，因此该结果不能直接解释为只连续录制12.8秒即可达到同样性能。

这是一项每位参与者使用自己数据进行个性化的跨会话研究，不是跨用户零样本实验。样本量和研究时长也不足以证明长期佩戴或所有人群中都有相同性能。

来源：§6.1–6.3、图8。

## 09. 手表部署与产品化：原型做到了什么？（3 分钟）

论文原型运行在 Apple Watch Series 10 上。每个输入窗口长2.56秒，窗口步长为1.28秒，因此在连续采样后大约每1.3秒可以得到一个新窗口。论文报告窗口就绪后，编码器与分类头的计算时间约为23.8毫秒。

窗口形成时间与模型计算时间是两个不同的量，23.8毫秒不能直接当成从动作开始到首次输出的完整延迟。编码器约有2140万参数，半精度权重约40.8 MB，论文报告每窗口计算量约8.83 GFLOPs。权重文件大小也不等于运行时峰值内存。

大规模自监督预训练在离线环境完成，手表上快速训练的是线性分类头。论文没有直接测量持续运行时的电池消耗和温度。

从原型走向产品，还需要验证目标设备的存储、运行时内存、延迟、功耗和跨会话误报。更换编码器后，旧特征和个人分类头不一定兼容，需要重新验证，必要时重新提取特征并训练。这些版本管理与量产流程属于工程建议，不是论文已经验证的能力。

来源：§4.3。

## 10. 论文结论与下一步实验（2.5 分钟）

总结这篇论文，TransfHAR 先利用丰富的粗粒度腕部数据进行自监督预训练，再冻结编码器，用少量个人标注训练线性分类器。公开数据集实验与受控用户研究表明，这种表示可以迁移到论文测试的细粒度活动。

当前证据也有明确边界：短窗口可能遗漏过程活动的长程步骤信息；10人研究不能代表长期漂移和所有人群；电池消耗、发热和长期自然使用尚未直接验证。

后续评估需要在一致的数据划分下比较手工特征、从头训练的小模型与冻结表示，并采用独立会话、跨用户和跨天测试。同时评估未知动作拒识、设备资源占用和连续运行能耗。

来源：§7–8。
